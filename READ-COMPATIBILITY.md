# Native Work read compatibility

October 17, 2026. Source follow-up to merged iOS PR #1. This adds compatibility for already-authorized reads; it does not install a receiver, create an assignment, or authorize an access request.

## Supported connections

| Approved disclosure | Issuer result | Signed read transport | Work reader |
| --- | --- | --- | --- |
| `devgraph.native-read-scope.v2` | `devgraph.native-read-result.v2` | `/devgraph/native-read/v2/requests` | Original five kinds; ID pagination and numeric metadata |
| `devgraph.native-read-scope.v3` | `devgraph.native-read-result.v3` | `/monitor/wallet-access/v1/requests` | Six kinds including Todo; canonical progress, revision-bound pages, separate detail and related-work reads |

Both use the existing native v2 challenge/enrollment endpoints and the unchanged `castalia.read-credential.v1` / `castalia.read-presentation.v1` formats. The exact approved disclosure is already retained by Rust in encrypted local storage. Its schema selects the transport after unlock; no new setting, credential migration, or silent downgrade is introduced. Unsupported versions and mismatched result versions fail before persistence.

The shared Wallet pin and native ABI remain unchanged. Actual native-core tests verify the modern permissions across approval, issuer verification, durable storage, unlock and per-call signatures. The new browser consent APIs are not required to read with an existing assigned credential.

## Native behavior

- Consent includes operations and relationship types, alongside issuer, receiver, Work/Arena selectors, archived visibility and expiry. A disclosure that hides an extra signed permission is rejected.
- Modern lists retain the server's snapshot revision and resource cursor. They do not infer completion from page length or substitute the old last-ID cursor. A changed snapshot fails with refresh guidance rather than combining revisions.
- Modern list metadata uses string priority/version fields and omits descriptions. Details use the separately granted `get` operation. When only list access is available, the app labels the item as a summary.
- Related-work links use only disclosed relationship types; the receiver continues to enforce the exact anchor/resource scope before returning related items. Related lists paginate with the server's resource cursor.
- Unknown progress is displayed as “Progress not recorded.” No progress is inferred from lifecycle stage, and nothing is written to Devgraph.
- Locking, network changes and denied/expired authority invalidate pending reads. Existing wallet creation, recovery, membership and network consent remain separate.

## Verification

`Tests/ZenithKitTests/Fixtures/devgraph-monitor-read.json` is generated by the actual public Devgraph projection code. It records its producer commit and uses fixed timestamps and synthetic Work. Regenerate it in that repository's Python environment:

```sh
python3 scripts/export-read-contract-fixtures.py \
  --devgraph-source /path/to/devgraph \
  --output Tests/ZenithKitTests/Fixtures/devgraph-monitor-read.json
```

`ReadContractTests` exercises both scope versions, wrong-version result rejection without persistence, hidden permission expansion, legacy-contract isolation, actual Rust approval/credential storage/reload/signing, modern pagination, details, related reads, ungranted relations and changed snapshots. The test issuer uses disposable in-memory keys and a stub HTTPS transport. It verifies Wallet signatures but does not replace the separate real secS/receiver integration gate.

Run `swift test` and compile the full Simulator app. Physical iPhone LAN/Tailscale reads, VoiceOver/large-text journeys, real receiver narrowing/revocation/renewal and final package qualification remain separate checks. This source change does not install anything on the phone.
